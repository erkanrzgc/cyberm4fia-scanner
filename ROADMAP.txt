(intent agent + sandbox + self-healing + meta-tools + MCP) on

Faz 13 — vulture deep-dead-code scan + coverage baseline
-------------------------------------------------------

Goal
    Catch dead code that AST orphan scan missed (instance methods called
    on never-instantiated classes, attribute-style usage on dynamic
    objects, etc.). Establish a baseline test-coverage number.

Steps
    1. Install (if not already):
           pip install --user vulture coverage
    2. Run vulture with min-confidence 80 (whitelisted internals):
           vulture core/ modules/ utils/ scripts/ \
               --min-confidence 80 --exclude='*/tests/*' \
               > docs/_audit/VULTURE_REPORT.txt
    3. Triage each finding into:
           DELETE      (truly dead, no caller anywhere — remove)
           KEEP+IGNORE (dynamic dispatch / plugin / public API — add to
                       vulture whitelist file)
           INVESTIGATE (false positive but worth a closer look)
    4. Apply DELETE batch (typically 5-15 names per file).
       Commit each kind of change as its own atomic commit.
    5. Coverage baseline:
           coverage run -m pytest tests/ -q
           coverage report --skip-covered --sort=cover \
               > docs/_audit/COVERAGE_REPORT.txt
           coverage html -d docs/_audit/htmlcov/
       Goal: capture the current % (no target — just a baseline).
    6. Commit: chore(cleanup/faz13): vulture+coverage baseline

Exit criteria
    - VULTURE_REPORT.txt + COVERAGE_REPORT.txt under docs/_audit/.
    - vulture whitelist file vulture.toml (or a pyproject.toml section)
      committed listing the KEEP+IGNORE names.
    - pytest tests/ still 683 passed.

Risks
    - vulture has false positives on dataclasses, Protocols, plugin
      dispatchers. Triage MUST be manual — never apply --remove blindly.
